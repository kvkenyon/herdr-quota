## Contract boundary

- Runtime dependency: `quota-axi@~0.1.29`, resolved by the lockfile. The tilde range accepts compatible 0.1.x patch fixes and prevents an automatic minor-contract jump.
- Accepted response: top-level schema version 5 with an ISO `generatedAt` and provider array.
- The refresh is scoped with `--provider claude,codex,cursor,kimi,grok,copilot`, and adaptation drops future provider IDs even when one is returned. Only an entry whose provider ID cannot be read at all is kept as a visible error card.
- Provider adaptation is independent. A malformed provider becomes an error card while valid siblings continue rendering.
- Unknown fields are ignored. Unknown window and tier IDs inside an allowed provider are preserved with quota-axi's own label (for example a future Kimi `limit:<n>`), never reclassified.
- Unknown percentages, resets, pace, or spend stay absent and render as `--` or `unknown`. They are never coerced to zero.
- A top-level schema-version change becomes an allow-listed incompatible-output failure while preserving the previous in-memory reading. Updating that boundary requires fixtures, adapter tests, this table, and a dependency-range review.

## Security boundary

Do not add credential parsing, cookie import, token refresh, or vendor response persistence to this plugin. When a provider changes, update or contribute to `quota-axi` first, then adapt its published normalized contract here. Whole-collector display state is a closed allow-list: timeout, missing executable, incompatible output, or generic network/process failure. Arbitrary stderr, response bodies, authorization headers, local account identifiers, credential paths, payload fragments, and terminal controls are drained or discarded rather than forwarded.

Local history does not persist the schema-v5 response. `src/history.ts` creates a separate schema-v2 allow-list. It contains only collection time, marketed provider/scope/limit display identity, effective remaining percentage, reset time, authoritative pace state/reserve, authoritative runway state/projection, and finite data-health/auth eligibility. Schema-v1 files migrate in memory. A read does not change the file. The next write uses schema v2. The path stays `history-v1.json`. The file is bounded to 512 snapshots or 30 days. It deduplicates equivalent samples within 15 minutes and uses private same-directory temporary-file replacement. An entirely stale, signed-out, unavailable, error, or unknown-semantics collection produces no write. In mixed reports, ineligible providers retain only finite gap eligibility and no quota facts.

Preferences have an independent boundary in `src/settings.ts`. `${XDG_CONFIG_HOME:-~/.config}/herdr-quota/settings.json` contains only schema version 3, the finite supported-provider order, hidden supported-provider IDs, `remaining` or `used` meter mode, `off`/`25`/`10`/`5` remaining-capacity policy, and forecast-before-reset boolean. Schema-v1 and schema-v2 settings migrate in memory. Schema-v1 settings use cues-off. A read does not change the file. The next save writes schema v3. Serialization cannot include account IDs, quota payloads, credentials, authentication facts, raw errors, history samples, or provider-output paths. Private atomic replacement preserves the last valid ordinary file on failure. Malformed current content is privately quarantined. Unsupported schemas remain untouched. Unknown fields and provider IDs are ignored. Symlink and non-regular targets are refused. Settings affect rendering, visible-provider selection, and local transition evaluation only. They never change collection, upstream quota semantics, credential access, retry scheduling, or quota-history storage.

Transition audit/dedupe state has its own finite boundary in `src/transitions.ts`. `${XDG_STATE_HOME:-~/.local/state}/herdr-quota/transitions-v1.json` uses schema v2. Schema-v1 files migrate in memory. A read does not change the file. The next state write uses schema v2. The path does not change. The file contains at most 256 events from the last 30 days: marketed provider/scope/limit identity, finite policy, reset-cycle identity, transition/baseline kind, event timestamp, and optional acknowledgement timestamp. It persists no percentage, quota payload, account, credential, path, output/error, token, source text, or arbitrary provider field. Threshold and forecast evaluation consumes only eligible `src/history.ts` facts from visible providers. Stale/auth/unavailable/error/unknown states and whole-check failures add no transition. Private owner-only atomic replacement, future-schema preservation, malformed/clock rollback segmentation, and unsafe-target refusal keep a failed transition write from producing an in-memory cue that could repeat after restart.

The closed schemas now allow `claude`, `codex`, `cursor`, `kimi`, `grok`, and `copilot`. Herdr Quota 0.3.x supports settings v2, history v1, and transition state v1. It sees the new versions as future schemas and preserves their bytes. Pi has no provider card.

## Collection and freshness

The pane invokes only the plugin-local executable described above. It refreshes once on open and again five minutes after a successful attempt and isolated history/transition update complete; collectors never overlap. Transition evaluation adds no collector and no process: it runs after a usable collection on that same serialized refresh path. On open, it may compare retained trustworthy samples for catch-up without claiming continuous monitoring. A whole-collector failure preserves the last in-memory report, suppresses prior history alerts, shows the scheduled retry countdown, and retries after 10, 20, then at most 30 minutes; it cannot create a quota transition. Manual refresh preempts the active child and resets scheduling. Provider-level stale, auth, rate-limit, and error states remain quota-axi-owned data states rather than being converted into collection failures or local estimates. Closing the pane cancels pending refresh timers and terminates an active child. No notification, toast, sound, badge, daemon, watcher, scheduled process, or OS integration is used.
